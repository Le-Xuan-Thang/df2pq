# Engine benchmarks

How long df2pq takes with each engine, and what to choose. All numbers come from
`tools/benchmark_engines.py`, which uses the app's own conversion code, so you
can reproduce them on your machine (see [Reproduce](#reproduce)).

## Summary

| Your situation | Fastest choice | Notes |
|---|---|---|
| Many small or medium files | **PyArrow** with **Parallel files** 8–32 | 5–12× faster than one file at a time; values exact |
| Few large files | **cuDF** (GPU), or PyArrow with Parallel files = number of files | cuDF ≈ 2.3× PyArrow per file |
| Values must match the source text exactly | **PyArrow** or **pandas** | cuDF can differ in the last digit (≤ 4 ULP, ≈ 1e-15 relative) |
| Excel or Pickle files | **pandas** | Parallel files works with pandas too |
| Destination on an NTFS/exFAT drive in Linux | Convert to a native Linux drive first, then copy | The FUSE driver is single-threaded; see results B |

**Parallel files** (Run tab) converts several files at once, one process each.
It applies to PyArrow and pandas; cuDF converts one file at a time on the GPU.
Each process holds one file in memory, so lower it for very large files or on
machines with little RAM.

## Results

Measured on 2026-11-17 with output written as Parquet and the default
damaged-row check on. *Per file* is the batch time divided by the number of
files; *throughput* is CSV megabytes read per second.

### A. 200 files of 9.5 MB, written to a RAM disk (tmpfs)

| Engine | Parallel files | Time | Per file | Throughput | Values vs. source text |
|---|---|---|---|---|---|
| cuDF | 1 | 8.9 s | 44 ms | 213 MB/s | up to 4 ULP off |
| PyArrow | 1 | 16.5 s | 82 ms | 114 MB/s | exact |
| pandas | 1 | 59.1 s | 295 ms | 32 MB/s | exact |
| PyArrow | 8 | 3.4 s | 17 ms | 561 MB/s | exact |
| PyArrow | 32 | 1.4 s | 7 ms | 1,391 MB/s | exact |
| PyArrow | 64 | 1.2 s | 6 ms | 1,540 MB/s | exact |
| pandas | 32 | 3.2 s | 16 ms | 581 MB/s | exact |

### B. The same files, written to an NTFS partition (ntfs-3g/FUSE) on NVMe

| Engine | Parallel files | Time | Per file | Throughput | Values vs. source text |
|---|---|---|---|---|---|
| cuDF | 1 | 12.7 s | 63 ms | 149 MB/s | up to 4 ULP off |
| PyArrow | 1 | 39.4 s | 197 ms | 48 MB/s | exact |
| pandas | 1 | 91.1 s | 455 ms | 21 MB/s | exact |
| PyArrow | 8 | 8.4 s | 42 ms | 226 MB/s | exact |
| PyArrow | 32 | 5.0 s | 25 ms | 378 MB/s | exact |
| PyArrow | 64 | 6.1 s | 31 ms | 308 MB/s | exact |
| pandas | 32 | 5.1 s | 26 ms | 367 MB/s | exact |

Writing through ntfs-3g is 1.4× (cuDF) to 3.6× (PyArrow, 32 parallel files)
slower than to the RAM disk, and more than about 32 parallel files makes it
slower again: every write goes through one single-threaded `mount.ntfs`
process. The drive itself is not the limit.

### C. 5 files of 158 MB, written to a RAM disk

| Engine | Parallel files | Time | Per file | Throughput | Values vs. source text |
|---|---|---|---|---|---|
| cuDF | 1 | 1.5 s | 299 ms | 529 MB/s | up to 4 ULP off |
| PyArrow | 1 | 3.4 s | 673 ms | 235 MB/s | exact |
| pandas | 1 | 14.3 s | 2,864 ms | 55 MB/s | exact |
| PyArrow | 5 | 1.5 s | 305 ms | 518 MB/s | exact |

With few files, parallelism is limited by the number of files.

## How the numbers were made

- **Data:** synthetic headerless CSV, `;`-separated, a time column and 8 float
  columns written with all 17 significant digits (60,000 or 1,000,000 rows),
  generated by the tool with a fixed seed.
- **One file at a time:** the same converter the app uses; each engine first
  converts one untimed file, because library loading and GPU start-up happen
  once per session in the app.
- **Parallel:** the app's batch runner with *Parallel files* set, including the
  start-up of the worker processes.
- **Values:** the first file's output is compared with the exact value of every
  number in the CSV text. ULP = unit in the last place of a 64-bit float.
- **Machine:** Intel Xeon Platinum 8592+ (256 hardware threads), NVIDIA RTX 6000
  Ada 48 GB (driver 580.178.04), Linux 6.12; Python 3.13.17, PyArrow 26.0.0,
  pandas 3.0.6, cuDF 26.10.02.
- **Caveat:** the machine was shared during the runs (load average 8–59).
  Repeated runs kept the same ranking, but absolute times varied by about 30%;
  compare engines with each other rather than with these exact numbers.

## Reproduce

```bash
uv run python tools/benchmark_engines.py --data /tmp/df2pq-bench --output /tmp/df2pq-out \
    --files 200 --rows 60000 --engines cudf,pyarrow,pandas,pyarrow:8,pyarrow:32
```

`engine:N` uses N parallel files. Put `--output` on the drive you will convert
to, because the destination filesystem can matter as much as the engine. The
output folder is deleted after each engine; the generated CSV files are kept in
`--data` for the next run.
